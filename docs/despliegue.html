Despliegue

La aplicación se despliega en Heroku con el buildpack de Node.

Cómo funciona el build

El package.json de la raíz define heroku-postbuild, que:

  1. Instala y compila el frontend (Vite).
  2. Copia el resultado a backend/public.
  3. Instala y compila el backend (TypeScript).

El proceso web (Procfile) arranca node backend/dist/server.js, que sirve API y frontend. Al arrancar, initDb crea y migra las tablas.

Desplegar

git push heroku main

Y, para tener copia del código en GitHub:

git push origin main

Variables de entorno (config vars)

Se configuran en Heroku, no en .env. Mínimas para funcionar:

VariableDescripción
DATABASE_URLLa inyecta el add-on Heroku Postgres.
SESSION_SECRETCadena larga y aleatoria.
ADMIN_USERUsuario admin (por defecto admin).
ADMIN_PASSWORD_HASHHash b64:... generado por gen-admin.
ADMIN_TOTP_SECRETSecreto TOTP generado por gen-admin.
STAFF_PASSWORDContraseña compartida del equipo de puerta.
RESEND_API_KEYAPI key de Resend.
EMAIL_FROMRemitente del dominio verificado (ej. entradas@maken-events.app).
PARTY_NAMENombre del evento.
heroku config:set SESSION_SECRET="…" STAFF_PASSWORD="…" \
  RESEND_API_KEY="re_…" EMAIL_FROM="entradas@maken-events.app" \
  --app maken-events

Generar credenciales del admin

cd backend
npm run gen-admin -- "TuContraseñaSegura"

Muestra el ADMIN_PASSWORD_HASH, el ADMIN_TOTP_SECRET y un QR para escanear con tu app de autenticación. Copia los dos valores a las config vars.

Dominio y email

  • Dominio: maken-events.app apuntado a Heroku (ANAME en la raíz, CNAME en www), con certificado automático (ACM).
  • Email: Resend con el dominio verificado (registros SPF/DKIM en el DNS). Sin esa verificación, los correos irían a spam.
Si reinicias o reseteas la base de datos con la app corriendo, reinicia el dyno (heroku restart) para que initDb vuelva a crear las tablas.
