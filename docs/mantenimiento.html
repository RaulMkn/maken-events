Copias de seguridad

Estrategia recomendada, sobre todo antes del evento:

  • Backup de Heroku (captura y descarga bajo demanda): 
    heroku pg:backups:capture --app maken-events
heroku pg:backups:download --app maken-events
  • Exportar CSV desde el panel admin: copia legible de la lista y respaldo de puerta.
  • Réplica local en Docker (ver abajo): copia navegable completa.
Haz un backup un par de días antes de la fiesta (cuando ya esté casi toda la gente registrada) y otro la víspera.

Réplica local en Docker

El script scripts/replica-local.sh descarga la base de datos de producción y la restaura en una PostgreSQL local en Docker (no necesitas pg_restore instalado: se ejecuta dentro del contenedor).

./scripts/replica-local.sh

Deja la copia accesible en:

postgres://postgres:postgres@localhost:5433/fiesta

Puedes lanzarlo tantas veces como quieras para refrescar la copia. Apaga el contenedor con docker stop fiesta-replica (los datos se conservan).

El fichero .dump descargado contiene datos personales. Guárdalo a buen recaudo o bórralo. Está excluido del repositorio en .gitignore.

Limpiar datos de prueba

  • Borrado individual: botón "Eliminar" de cada asistente en el panel.
  • Reset completo: si reseteas la BD desde Heroku con la app corriendo, reinicia el dyno para recrear las tablas: 
    heroku restart --app maken-events

Prueba de humo

Contra una instancia local en marcha, valida el flujo crítico (registro → confirmar → QR → verificar → CSV):

cd backend
npm run smoke-test
