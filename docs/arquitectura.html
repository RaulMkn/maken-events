Arquitectura

Una sola aplicación Node que sirve la API y el frontend, con PostgreSQL detrás.

Visión general

En producción hay un único proceso: un servidor Fastify que expone la API bajo /api y, además, sirve los ficheros estáticos del frontend (React ya compilado). No hay servidor web aparte ni proxy: Heroku pone el HTTPS por delante y el propio backend responde todo. 

Navegador
   │  HTTPS
   ▼
Heroku (router + TLS)
   │
   ▼
Fastify  ──►  /api/*           (registro, admin, staff, entrada)
   │      └─►  resto de rutas    (index.html + assets de React)
   ▼
PostgreSQL (Heroku Postgres)

Flujo de una petición

  • Las llamadas a /api/... las manejan las rutas del backend.
  • Cualquier otra ruta devuelve index.html (SPA): el enrutado del cliente (/, /halloween, /admin, /staff…) lo resuelve React Router.

Backend

Organizado en backend/src:

FicheroResponsabilidad
server.tsArranque de Fastify, cabeceras de seguridad (helmet + CSP), rate limiting, cookies, registro de rutas y servido del frontend.
config.tsLee y valida las variables de entorno. Falla al arrancar si falta algo crítico en producción.
db.tsPool de PostgreSQL, creación del esquema y migraciones idempotentes (initDb), helpers de ajustes.
routes/registro, auth (admin), admin, staff, entrada.
lib/auth (argon2 + TOTP), sesion (JWT en cookie), proteger-admin/proteger-staff (guardas), email (Resend + QR), validacion.

Frontend

React + Vite en frontend/src. Páginas principales:

RutaPáginaDescripción
/EventosHome neutra: selector de eventos.
/halloweenLandingInfo del evento y botón de registro.
/halloween/registroRegistroFormulario + condiciones.
/adminAdminLogin con MFA + panel (Asistentes / Finanzas).
/staffStaffLogin simple + lector de QR.

Build y despliegue

El package.json de la raíz orquesta el build de Heroku (heroku-postbuild): compila el frontend, copia el resultado a backend/public y compila el backend. Al arrancar, initDb crea y migra las tablas automáticamente. Detalles en Despliegue.
